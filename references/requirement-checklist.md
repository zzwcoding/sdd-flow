# 需求逼问覆盖清单

阶段 1（需求对齐）的逼问地图。逼问引擎是 `grill-with-docs` 的追问纪律，本清单只负责一件事：**该问的维度一个不漏，每个维度都被显式确认过**。维度与"管理系统"无绑定——对非管理系统，⑤⑥⑦ 大概率标 N/A，但**标注动作不能省**。

## 使用规则

1. **按维推进，逐维关闭**：按下面 11 个维度依次逼问；每个维度结束时必须在 PRD 里落结论，并标注 `适用` 或 `不适用（N/A + 一句话理由）`。**沉默跳过 = 没问。**
2. **A/B 分流**，标注直接写在 PRD 对应条目尾部：
   - **A 类（行业通用）**：AI 自动补全，写入 PRD 并标 `[AI自动补全]`。不拿这类问题消耗用户。
   - **B 类（企业专属、猜错有真实业务风险）**：必须带建议提问，标 `[待确认]`，用户确认后改标 `[已确认]`。
   - 判断标准：换一家同行业公司，答案会不会不同？会 → B 类；不会 → A 类。
3. **固定提问格式**（所有 B 类问题统一用）：

   ```
   问题 N：<一句话>
   AI 建议：<建议方案>
   理由：<为什么这样建议>
   其他选项：<2-3 个备选，各带代价>
   快捷回复：按AI建议 / a / b / c / 其他意见
   ```

4. **硬门禁**：PRD 中存在任何 `[待确认]` → 不得标记定稿。`docs/prd.md` 顶部带 `状态: 粗稿 | 逼问中 | 已定稿`；spec gate 机器校验：标 `已定稿` 而全文仍有 `[待确认]` → FAIL。

## 11 个维度

### ① 边界与用户

- 问：系统做什么、明确不做什么；用户/调用方是谁；在什么环境下用；怎样算成功（可观察的结果）。
- 关闭标准：PRD 有"做什么 / 不做什么"两节；用户清单完整。

### ② 业务对象与关系

- 问：领域里有哪些名词级实体；各自的关键属性和状态；状态怎么流转；实体之间什么关系。
- 关闭标准：对象清单 + 关系描述落盘（文字够用；要图走 archify）。

### ③ 功能与规则

- 问：每个对象上发生什么操作；每个操作的校验规则、计算规则、异常分支。
- 关闭标准：功能清单覆盖所有对象；每条规则是可判断真伪的陈述句。

### ④ 跨对象联动

- 问：A 发生某变化时，B 要跟着发生什么（联动、派生、通知、同步）。
- 关闭标准：联动清单，或"N/A，对象间无联动"。

### ⑤ 流程与审批 / 状态机

- 问：有没有多步流程、审批节点、状态机？串行还是并行？驳回、撤回、超时怎么处理？
- 关闭标准：有 → 流程描述 + 各节点角色；无 → 标 N/A。

### ⑥ 查询、统计与报表

- 问：用户要看什么列表、指标、报表？维度和口径是什么？
- 关闭标准：指标清单，或标 N/A。

### ⑦ 角色与权限、数据隔离

- 问：谁能看什么、做什么；有没有数据隔离（租户/组织/个人）；权限粒度到功能还是到数据。
- 关闭标准：权限矩阵或"单角色无隔离"结论，或标 N/A。

### ⑧ 输入输出与外部集成

- 问：对接哪些外部系统；导入导出什么格式；谁是上游谁是下游；对接失败怎么办。
- 关闭标准：集成清单，或"无外部依赖"结论。

### ⑨ 异常与边界

- 问：每条主路径的失败路径；重试与幂等；并发冲突；中断恢复；脏数据。
- 关闭标准：每个功能至少回答过一次"失败了会怎样"；边界情况进了 PRD 行为约定。

### ⑩ 量级与非功能

- 问：数据量、并发量、延迟要求；安全与合规约束（脱敏、审计、留存）。
- 关闭标准：量级有数字（估算也算）；无硬要求也要显式写"无特殊要求"。

### ⑪ 数据生命周期

- 问：数据怎么初始化、迁移；要不要归档、软删除、审计留痕；谁有权删数据。
- 关闭标准：有结论，哪怕是"全不做"。

## 与其他阶段的衔接

- 本清单只在阶段 1 全量过一遍。阶段 3 写 spec 时发现某维度当初标了 N/A 但实际适用 → 回阶段 1 补逼问，不许就地带过。
- 阶段 2 做模块划分时，`[AI自动补全]` 的内容如涉及模块边界，同样要经用户确认——自动补全省的是逼问成本，不豁免设计确认。
